# 280Ah储能电池舱热管理平台 v7：修复48小时终点多积分问题

## 本版修复重点
上一版仿真在 `t=duration_h` 的终点仍然执行了一次完整时间步，导致：
- 48小时终点额外累计了5分钟设备能耗和热负荷；
- 终点恰好落在周期负荷切换点，程序把下一周期的高负荷错误地计入本次48小时仿真；
- 曲线末端可能出现不合理的突增。

v7将仿真改为按时间区间积分：
- 48小时、300秒步长 = 576个真实积分区间；
- 最后一段积分结束于48.000小时；
- 48.000小时只记录状态，不再执行48.000小时之后的下一步；
- 非整除步长的仿真时长会自动缩短最后一个积分步，确保终点严格等于用户设定时长。

## 设备协同控制
保留v6的滚动预测MPC：候选风机转速、风阀开度和空调负荷组合同时参与寻优；低环境温度时优先风机与PCM，预测温度风险升高或风机换热温差不足时再启用空调。空调仍然保留，并非人为禁用。

## 47h / 48h端点核验
见 `endpoint_integrity_validation_v7.csv`：
- 47小时结果终点严格为47.000 h，采样点564；
- 48小时结果终点严格为48.000 h，采样点576；
- 两种时长最后一个步长均为5分钟；
- 48小时末端热负荷为0.9 kW（原周期工况在47–48小时处于低负荷阶段），不会把48小时之后的新周期高负荷算进来。

默认30℃、1C工况的能耗：
| 仿真时长 | 固定送风 | 固定阈值 | 双预测MPC |
|---|---:|---:|---:|
| 47 h | 13.743 kWh | 8.001 kWh | 1.687 kWh |
| 48 h | 14.035 kWh | 8.175 kWh | 1.716 kWh |

这些是简化模型仿真结果，不是实测节能率。48小时比47小时增加的能耗对应真实增加的1小时运行，不存在终点额外5分钟。

## 运行
```bash
pip install -r requirements.txt
streamlit run app.py
```

若旧Streamlit进程仍在运行，请先停止旧进程（终端按Ctrl+C），再重新启动，以免浏览器仍连接旧代码。
