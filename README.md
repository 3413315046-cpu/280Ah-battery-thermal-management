# 中国中车杯｜280Ah储能电池舱智能热管理网站 v7.0（三策略、无空调）

## 1. 本版本做了什么

- 完全移除空调制冷/压缩机及其设备控制和能耗：只保留EC轴流/离心舱级风机、电动风阀。
- 使用同一套12热区+24PCM焓节点的数值热模型，比较三种控制模式：
  1. 固定送风：运行开始，风机固定转速持续送风，风阀固定；无温度反馈、无预测。
  2. 固定阈值：根据当前热区最高温达到35℃启动风机，低于34℃关闭；高于39℃强制100%转速，温度控制规则不涉及预测。
  3. 双预测MPC：每2/5分钟（默认5分钟）使用未来10/20/30分钟（默认20分钟）热状态，枚举风机比例、风阀开度和热区均衡送风模式，优选温度、温差和设备能耗综合代价。
- 温度初值默认30℃，环境30℃，1C；页面允许运行1–48小时。多小时采用有放电/充电/静置的负荷曲线，而非物理上不成立的连续48小时1C放电。
- PCM演示固定参数：密度1100 kg/m³、显热比热1740 J/(kg·K)、导热率3.5 W/(m·K)、相变温区38–43℃、潜热120 kJ/kg；原始CAD 24侧PCM区域几何体积约0.04651 m³，仅为几何候选体积。
- 6个导航页，包含综合指标、热区温度与温差、PCM相变储热、预测与调控、风机能耗、144芯点位热区投影，支持CSV结果导出。
- 浅色主题采用 `.streamlit/config.toml`，修复旧版深色字体看不清的情况。

## 2. 网站部署（原GitHub仓库，无需新建Streamlit项目）

1. 解压此包（不要把ZIP直接上传GitHub）。
2. 打开原 GitHub 仓库 `https://github.com/3413315046-cpu/280Ah-battery-thermal-management`。
3. 上传解压后的 `app.py`、`thermal_engine.py`、`requirements.txt`、`README.md`、`.streamlit/config.toml` 以及 `data/` 的CSV/JSON文件到**仓库根目录**（其中 `.streamlit` 和 `data` 必须保留目录结构）。
4. 在同一 `main` 分支 `Commit changes`。Streamlit Cloud 将读取根目录的 `app.py` 重新部署。
5. 如果网页出现 `ModuleNotFoundError: No module named 'thermal_engine'`，通常是 `thermal_engine.py` 未上传到仓库根目录。

**推荐本地运行：**
```powershell
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python -m streamlit run app.py
```

## 3. 模型实现与限制（保留在工程说明中，不占网站独立栏目）

### 热模型与参数
- 电芯热源：`Q_i = I(t)^2 * R * 12 * heat_factor_i`，其中候选 `R=0.25mΩ`，`mass=5.49kg`，`c=1000J/(kg·K)` 需用真实280Ah电芯数据辨识。忽略Bernardi可逆熵热。
- 热状态：12个电芯热区（每区12个电芯）和24个PCM焓状态。24PCM区域由CAD几何CSV推导，质量按固定密度估算。焓式：`h(T)=cp*T+L*clip((T-38)/5,0,1)`；采用焓温反演，计算PCM剩余潜热。
- 热交换：电芯到空气、电芯到PCM、PCM到空气及邻区之间的导热均以等效热导建模；所有换热系数为工程候选，未由CFD或实验参数辨识。空气温度是恒定环境温度，没有完整风道CFD。
- 仅风机与风阀主动调节；风机功率 `P=P_rated*(n/n_rated)^3`；风阀执行器按动作每次5W×15s近似计电。风量采用额定风量×调速比例×安装折减函数，**没有标定的完整系统阻力曲线**，P-Q数据为设备参考，不代表真实工作点已校核。
- 12热区最高温/最大温差属于降阶结果；144芯3D温度显示是把每热区温度映射到12个CAD点位，**不是独立求得的144芯温度场**。最终192状态求解器尚未作为此网页实时计算后端使用。
- 该PCM参数组来自用户提供的旧Fluent/演示参数表，**不是**王佳等宽温域WT-CPCM论文三阶段502.24kJ/kg材料的已证实物性组合；二者不能混同。

### 三策略公平性
- 三组共享环境温度、放电倍率与电流时序、电芯与PCM参数、风机和风阀设备参数、区域热网络，**只改变控制策略**。
- 固定送风组根据定义从开始就恒速送风；阈值与MPC组在温度较低时通常保持停机。这些启动机制是对比的核心，不是完全相同风机初始功率。
- MPC并不保证在所有工况同时实现“最低Tmax/最低能耗/最小温差”，软件将原样展示实际计算结果及未达标情况。
- 当前MPC是网格枚举+未来热模型预测，不是经过实测验证的硬件MPC，更不是目标192状态双预测与风阀系统的成熟闭环。
- 系统不配备空调，所以当环境温度与热源导致空气风冷能力不足时，模型可能达不到最高温目标或最大温差目标；这是应当如实呈现的设备能力限制。
- 预测窗口不等于仿真总时长。运行48小时不表示一次预测48小时。

## 4. 校验

运行：`python -m unittest discover -s tests -v`，包括：焓温反演、初始纯环境平衡、SOC一致放充电时序、三策略0–1的液相率及非负温度检验、48小时和高温工况可积性、累计能耗单调性。

网站v7.0由独立 `thermal_engine.py` 负责计算，`app.py` 负责交互和展示；避免界面代码混入物理求解，便于后续替换真正经校准的192状态热网络。
