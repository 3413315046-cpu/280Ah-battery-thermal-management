# 280Ah储能电池舱热管理平台 v8

## 本版解决的问题
此前双预测MPC的候选预测时域错误地使用了至少10小时，导致预测控制与设置的20分钟预测参数不一致；页面也可能继续显示旧缓存结果。v8进行了两项修复：

1. **真正按20/40/60分钟滚动预测**：每5分钟更新一次电池八区温度、温升趋势、环境温度、PCM状态，并重新搜索风机、风阀和空调组合。
2. **缓存版本隔离**：Streamlit计算函数加入MPC v8版本标识，避免继续显示旧控制器结果；页面显示“控制器v8”作为版本核对标记。
3. **48小时积分边界**：保留v7严格终点积分修复，48小时只累计至48.000 h，不执行终点之后的额外时间步。

## v8控制逻辑
- 风机：利用环境温差进行低功耗换热；当环境温度接近/高于电池温度时，风机换热能力自然下降。
- 风阀：在候选开度中调整气流分配，优先改善高温分区，抑制最大温差。
- 空调：作为可选补偿执行器，不固定开启。预测电池温度逼近控制目标、风机换热温差不足或PCM潜热缓冲不足时才提高空调负荷；无制冷需求时可以关闭。
- PCM：控制器读取PCM温度、液相率和剩余潜热状态。当前默认参数下PCM温度接近但尚未达到38℃相变起始温度，因此默认工况末端液相率仍为0%；这不代表液相率计算被强制清零，而是模型预测状态尚未进入相变区间。

## 默认工况验证（环境30℃、初始30℃、1C、完整充放电循环）
| 时长 | 固定送风总能耗 | 固定阈值总能耗 | 双预测MPC总能耗 | 双预测最高温度 | 双预测最大温差 |
|---:|---:|---:|---:|---:|---:|
| 46 h | 13.450 kWh | 7.827 kWh | **1.914 kWh** | 37.93℃ | 1.88℃ |
| 47 h | 13.743 kWh | 8.001 kWh | **1.953 kWh** | 37.93℃ | 1.88℃ |
| 48 h | 14.035 kWh | 8.175 kWh | **1.997 kWh** | 37.93℃ | 1.88℃ |

48小时默认工况双预测MPC能耗构成：
- 风机：0.903 kWh
- 空调：0.211 kWh（累计运行约5.17 h，按低负荷间歇介入）
- 风阀及辅助：0.8827 kWh
- 合计：1.997 kWh

与最低能耗对照组（固定阈值8.175 kWh）相比，默认工况模型计算节能约75.6%。双预测组最高温度低于38℃控制目标，最大温差低于3℃控制目标。

## 不同环境温度检查
`ambient_sweep_validation_v8.csv`提供20/25/30/35/40/45℃六种环境温度下三组仿真结果。环境温度越高，空调需求越大；在高环境温度下，如果要求电池温度低于环境温度，必须由空调承担制冷，能耗不可能仅靠软件控制消除。对比能耗时必须同时比较最高温度和最大温差，不能只追求能耗最低而放宽热安全约束。

## 重要科研说明
本平台为简化分区等效热模型仿真，尚不是实测或CFD验证结果。当前风机换热系数、舱级热容、PCM换热耦合和空调制冷量仍需通过CFD/实验标定。报告中的节能率只能表述为“模型仿真结果”，不可直接作为实测节能率。

## 运行方式
在Windows PowerShell进入解压目录后：
```powershell
pip install -r requirements.txt
streamlit run app.py
```
若旧版页面仍在运行，先在旧终端按 `Ctrl+C` 停止，再从本v8解压目录启动。启动后应能在页面顶部看到“控制器 v8”标识。
